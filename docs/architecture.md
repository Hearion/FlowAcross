# 流界 FlowAcross 技术架构

> 一套键鼠，自由跨屏。本文档记录第一版（v1）的技术选型和关键设计，随开发持续更新。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 核心逻辑 | Rust（`crates/flow-core`） | 无 IO 的纯逻辑：布局、坐标换算、切换判定、按键状态、协议编解码。可在任何平台单测。 |
| 平台层 | Rust + 各平台系统 API（`crates/flow-platform`） | macOS：CGEventTap / CGEventPost / NSPasteboard；Windows：低级键鼠钩子 / SendInput / 剪贴板（两边都按变化计数轮询，见第 7 节；不用 Raw Input，原因见第 4 节）。Linux：X11、Wayland（wlroots 系）、Wayland（GNOME / KDE 走 portal）三套实现，见第 12 节。 |
| 网络层 | Rust：QUIC（quinn + rustls）+ mDNS（mdns-sd）（`crates/flow-net`） | QUIC 自带 TLS 1.3 加密；可靠流传按键，不可靠数据报传鼠标绝对坐标；剪贴板走独立流，大文本不会阻塞输入。 |
| 桌面外壳 | Tauri 2（`app/src-tauri`） | 体积小、常驻内存低，托盘/菜单栏、开机启动、单实例都有官方插件。 |
| 界面 | React + TypeScript + Vite（`app/src`） | 设备布局图需要拖拽交互，Web 技术实现最省力。视觉规范见 `docs/design.md`。 |

## 2. 进程与模块关系

```
┌──────────────────────── 流界（单进程）────────────────────────┐
│  UI (WebView, React)  ←── Tauri commands / events ──→  Engine │
│                                                        │      │
│        ┌───────────────┬───────────────┬───────────────┘      │
│        ▼               ▼               ▼                      │
│  flow-platform     flow-net        flow-core（纯逻辑）         │
│  键鼠捕获/注入      发现/配对/QUIC   布局·切换·按键·协议        │
│  剪贴板/权限/休眠                                               │
└───────────────────────────────────────────────────────────────┘
```

- **Engine**（位于 `app/src-tauri`，后续可下沉为独立 crate）是一个 actor：接收平台事件、网络事件和 UI 命令，调用 `flow-core` 做决策，再驱动平台层和网络层执行。
- **推给界面的状态**：引擎把整份状态（`StateView`）作为 `state` 事件推给界面和托盘。每份带一个在状态锁里递增的序号：两个任务同时推送时先算出来的可能后到，界面和托盘丢掉比手里旧的。只影响显示的变化（附近的设备、文件清单、传输列表）只推状态，不重新同步控制器；传文件期间的进度单独走一个轻量的 `transfers` 事件（每秒最多 5 次，只带传输列表）。系统权限的查询结果一秒内复用，界面主动来要状态时（打开窗口、从系统设置回来）才重新查。
- **空闲时放慢**：没有任何设备连着时，心跳 / 停留计时的定时器从 40 毫秒放慢到半秒，显示器从每 6 秒枚举一次放慢到半分钟一次，锁屏状态不查。
- 每台电脑运行同一个程序，**对等**架构，没有固定的"服务端"。正在被用户物理操作的那台叫 **源设备**，被远程控制的叫 **目标设备**。任何一台都可以成为源。

## 3. 统一坐标空间

所有设备的所有显示器放在一个 **布局空间** 里，单位是 **逻辑点**（与缩放无关，≈ macOS 的 point、Windows 100% 缩放下的像素）。

- 每块显示器：`rect`（布局空间中的位置和逻辑尺寸）+ `scale`（缩放系数，物理像素 = 逻辑点 × scale）。
- 用户在布局图里拖动卡片，修改的就是 `rect.origin`。拖动时自动吸附到相邻卡片边缘。
- **Windows 多屏**：系统的虚拟桌面是物理像素，各屏缩放可以不同。每块屏"原点 ÷ 自己的缩放"得不到连续的排布（150% 主屏右边的 100% 副屏会隔开一截，反过来则重叠），所以由 `flow-core::layout::logical_arrangement` 从主屏出发，把物理上相贴的屏幕逐块贴到邻居的逻辑边上，沿边方向的错位按邻居的缩放换算。
- **鼠标速度**：平台层上报的位移已换算成逻辑点（macOS 事件本身就是逻辑点；Windows 钩子给的是物理像素，除以所在显示器的缩放），在目标显示器上按逻辑点移动。这样 4K@200% 和 1080p@100% 之间移动的"手感距离"一致。
- **布局在各台电脑之间同步**（`flow-core::layout::SharedLayout`，0.2.4 起，设置 › 通用里可以关）：每台电脑各有各的布局坐标系，原点不同，但每台设备的显示器矩形是它自己上报的、大家手里一样，所以两台设备偏移的差在哪台电脑上都该相同。同步的就是"各设备的偏移"这张表（`Message::Layout`），收到的一方整体平移到自己的位置不变（`rebased`），再照着摆其他设备。
  - 谁的算数：配置里记着布局的修改次数（`layout_rev`，用户每拖一次加一）和最后改动者（`layout_by`）。次数大的赢；一样大时（两边同时拖、或者都还没拖过）设备 ID 大的赢——任意两台比出来结果一致，不会来回覆盖。两边同时拖动时，输的那一方这次的拖动被覆盖。
  - 什么时候发：会话建立后、第一次给对方安排了位置之后、用户拖动之后、采纳了别人的布局之后（转给其他电脑：它们之间可能没有直接配对；同一份传回来不算新，不会转圈）、刚打开同步开关时。收到比自己旧的就把自己的回给对方。
  - 新配对的两台电脑各自都把对方默认放在自己右边，两份布局是矛盾的；现在配对后比一次，统一成一份（两台都没拖过时按设备 ID 定，等于随机选一边）。
  - 对端的数据不可信：设备数封顶、偏移必须是有限且不离谱的数、ID 合法不重复（`is_sane`）；换算后在本机摆出来有重叠（本机认识、对方不认识的设备挡在那里）就整份不用，保持原样。
- **跨边映射**：默认"连续映射"——光标从边缘离开时，沿边方向的布局坐标保持不变（和同一台电脑多显示器一致）；可选"按比例映射"——按边长比例换算，适合尺寸差很大的屏幕。

## 4. 切换与防误触

`flow-core::switching` 是纯函数状态机，输入"光标贴边事件 + 当前时间 + 按住的修饰键"，输出"切换 / 不切换"。

- 边缘必须有相邻显示器（布局里真正贴着）才会切换。
- 可选：按住指定修饰键才允许跨屏。
- 可选：贴边停留 N 毫秒才切换（停留期间离开边缘则重新计时）。
- 可选：角落死区，避免触发 macOS 触发角 / Windows 开始菜单时误切。范围是屏幕边两端各 48 个逻辑点（`flow_core::switching::CORNER_DEADZONE`），最多占这条边的两成。早先是 10 个点，光标稍微一滑就出去了，等于没有。
- **锁定在本机**：只限制本机键鼠切出去，边缘和快捷键切换都停止；若本机正在控制远端，立即释放远端按键并回到本机。对方仍可进入并控制本机，正在进行的入站控制、剪贴板和文件共享不受影响。
- **暂停共享**：停止双向键鼠、剪贴板和文件共享，立即结束已有控制并释放按键，取消正在发送和接收的文件，清空待接收和本机已提供的文件清单。设备连接保留，以便恢复；恢复后不会自动重启旧传输或补发暂停期间的复制内容，重新复制即可共享。单独暂停某台设备时，停止与该设备的双向键鼠、剪贴板和文件共享。本机在会话建立时和暂停状态变化时发 `Availability { accepting }`（`flow-core::switching::accepts_control`），对方据此不再切过来、正在控制的回到它那边，界面显示「对方已暂停」。目标侧收到 `Enter` 时也会再次判断（对方没来得及收到通知，或是旧版本），不接受就忽略它之后的输入。锁定不改变此通知。
- 按住鼠标按钮时不切换（v1 不支持跨设备拖拽，避免拖到一半按钮状态错乱）。
- **边缘浮光**：键鼠来到本机时（被别的设备滑入，或控制远端后穿过屏幕边回来），在它进来的那条屏幕边上闪一道品牌蓝的浮光，约 0.75 秒：整条边一道浅光带，进入点处一团更亮的光沿边散开。被滑入时落点来自 `Enter`，回到本机时控制器在 `Changed` 之后发 `ControlEvent::Returned(落点)`；引擎用 `Rect::nearest_edge` / `edge_fraction` 算出是哪条边、边上的哪个位置，交给 `flow_platform::edge_glow`，不改协议。快捷键切换、断线回到本机时不闪。浮层是原生窗口：不激活应用、不抢键盘焦点、鼠标事件穿透、盖在全屏应用之上；macOS 用 Core Animation 渐变图层（`macos_glow.rs`，窗口复用，要在主线程调用），Windows 用 DirectComposition 透明窗口在单独的线程里逐帧提交 BGRA 纹理（Direct3D 11，绕开 GDI 分层窗口合成的横向错位）（`windows_glow.rs`），形状和节奏的参数共用 `flow-platform::glow`。系统打开「减少动态效果」或关掉动画效果时只淡入淡出。设置里「跨屏时显示边缘浮光」可以关。不用网页窗口做：Tauri 的透明窗口在 macOS 上要开私有接口，显示时还可能抢走键盘焦点。
- 停留计时只在"往外推"时开始，单纯停在边上（比如点贴边的滚动条）不会触发。
- 快捷键（默认 Ctrl + Alt + ←/→，Mac 上 ⌃⌥←/→，可以在 设置 › 快捷键 里改）切到布局中左右相邻的设备，不受按住指定修饰键、贴边停留和角落死区限制；暂停共享或锁定在本机时不可用。自定义快捷键、切到指定设备和快捷键映射见第 5 节。
- 光标到达通往其他设备的边的最后一个逻辑点、且仍在朝边移动，就算"推出边缘"（系统会把光标限制在屏幕内，贴边后继续推不一定有位移）。

### 跨屏控制流程

- **源设备**：有已连接的设备时启动全局键鼠捕获（macOS CGEventTap，Windows 低级钩子），全部断开后卸掉（最多 2 秒内），不在没有设备可切时挂在系统的输入路径上。捕获回调同步调用 `input::Controller`，它只做内存计算并把消息投进会话的发送通道，决定每个事件放行还是拦截。
  - 本机状态：把光标位置换算到布局空间，交给 `EdgeSwitcher` 判断是否切换。平台层上报的是**移动前**的位置加这次的位移（两个系统含义一致，见 `CapturedEvent::MouseMove`）；离边缘超过 1 个逻辑点的移动直接跳过判定。
  - 控制远端：拦截全部输入（macOS 和 Windows 上例外：键码表里没有的键——Windows 的 Alt+PrtSc、Ctrl+Break 等——认不出来，照常留给本机；Mac 键盘上的音量、播放键走系统定义事件，事件监听没有接，也留给本机。PC 键盘的音量和播放控制键（播放 / 暂停、停止、上一首、下一首，键码 0xE8–0xEB）在键码表里，照常发给远端，Mac 收到后注入系统定义事件；Linux 的三套实现靠抓取 / 独占键盘，全部拦下）；`VirtualCursor` 在布局空间里按相对位移移动，把目标显示器内的绝对坐标发过去（`Enter` / `MouseMove`），按键和按钮按 `InputRouter` 分到"按下时所在的一边"。
  - 光标锁定：macOS 断开鼠标与光标的关联并隐藏光标；Windows 把光标停在离开的那个边缘点并拦截移动（暂不隐藏）；低级钩子上报的坐标不会被限制在屏幕内（实测），所以停在边上也能测到往外的位移。回到本机时光标放到跨回来的位置。
  - 控制期间每 500 毫秒发一次 `Heartbeat`；对方支持时 1.5 秒收不到 `HeartbeatAck` 就回到本机（见第 6 节）。
- **「键鼠在这里」的显示**：每台电脑只知道自己的键鼠在哪。本机没在控制别的设备时，默认标在本机；例外是别的设备刚主动结束对本机的控制（收到 `Leave`），这时键鼠跟着它回去了，标到它那边（`DeviceView::has_input`），直到本机有键鼠输入（控制器发 `ControlEvent::LocalInput`）、它断开，或本机又开始控制或被控制。看不到本机输入的系统（Linux 的 Wayland，`Limits::local_input`）不做这个推断。这是设备级的标记，不表示光标在这台设备的哪块屏幕上，有多块屏幕时界面写「键鼠在这台电脑」。
- **目标设备**：只接受当前控制者的输入并注入（macOS CGEventPost，Windows SendInput），同时记录它按下的键。收到 `Leave`、会话断开、或 3 秒没有任何消息时释放全部按键。
- **接管**：同一时刻只能有一个控制方，谁的物理键鼠在动谁就是源。A 控制 B 时，用户直接拿起 B 的鼠标推到 A：B 的控制器照常进入 A 并发 `Enter`，同时 B 结束"被 A 控制"（释放 A 按下的键，不再注入 A 的输入）；A 收到 `Enter` 时如果自己正在控制别的设备，先 `Controller::yield_control()`——释放远端按键、发 `Leave`、解锁本机光标但不挪动它——再接受 B 的控制。否则两边都以为自己是控制方，A 的光标一直被锁、本机键鼠被拦截转发，表现为流转异常、切不回来。
- 流界自己注入的事件带标记（macOS 事件 user data，Windows dwExtraInfo），捕获时直接放行，不会被当成本机输入。
- 鼠标坐标走 QUIC 数据报（`flow-net::moves`）：每条带递增序号；接收方一次读完已到达的数据报，只注入最新的一个，过时和乱序的丢掉。网络短暂停顿后光标直接跳到当前位置，不会像可靠流那样把积压的位置逐个重放。只有对方版本 ≥ 0.1.3（`DATAGRAM_MOVES_SINCE`）时才发数据报，否则仍走可靠流；点击、按键、进入/离开等其他消息始终走可靠流。数据报发送缓冲只有 16 KB，拥塞时 quinn 丢弃最旧的。两条通道之间没有先后保证，所以点击、滚轮、按键发出前，会把最近一次用数据报发出的位置在可靠流上补发一遍，保证"先移到那里再点"。
- 发送端对鼠标位置节流（`flow-core::throttle`）：两次发送至少间隔 4 毫秒，间隔内只保留最新位置，其他消息到来时先把待发位置发出。高回报率鼠标每秒上千个事件，逐条发送会让网络排队、远端注入跟不上而卡顿。「结束控制远端」日志记录这次的按键数、鼠标事件数和时长，可据此估算回报率。
- 已知网络问题：Mac 用 Wi‑Fi 时，AWDL 大约每 0.5 秒造成一次 60–100ms 的网络停顿（实测，关掉 awdl0 后消失），表现为跨屏每秒卡一下。鼠标位置改走数据报后，停顿后直接跳到最新位置，但停顿本身仍在；实测仍能感到卡顿，所以提供低延迟模式。
- **低延迟模式**（仅 macOS，`flow-platform::low_latency`，默认关闭）：第一次开启时通过 `osascript … with administrator privileges` 安装一个 launchd 守护进程（`/Library/LaunchDaemons/app.flowacross.awdl-guard.plist`，脚本在 `/Library/Application Support/FlowAcross/`，root 所有）。脚本和 plist 的内容以 base64 直接写在 root 命令里（`flow-platform::root_install`），由 root 写进只有 root 能写的目录、改名就位；不经过用户可写的临时文件，否则授权弹窗停留期间同一用户下的其他进程可以把文件换掉，换来以 root 身份常驻执行（0.1.6 及以前的问题）。守护进程每 0.5 秒检查：标志文件 `/tmp/app.flowacross.lowlatency` 存在（且属于当前登录用户，/tmp 谁都能写）且流界在运行时保持 `awdl0` 关闭，否则恢复它关掉的 AWDL。引擎在"开启了且有设备连着"时创建标志文件，断开、关闭开关、退出时删除；标志在 /tmp，重启自动清除；流界异常退出时守护进程也会恢复。设置里可以移除后台服务。
- 流界大部分时间在后台运行，启动时调用 `flow_platform::keep_responsive()` 关闭系统对后台程序的降速：macOS 登记延迟敏感活动并在 Info.plist 声明 `LSAppNapIsDisabled`（关闭 App Nap），Windows 关闭本进程的电源节流（EcoQoS）。否则打包后的正式版跨屏会卡顿。
- Windows 上进程注册了键盘 Raw Input 时，只要它自己的窗口在前台，系统就不再调用它的低级键盘钩子（实测）。Tauri 的窗口库 tao 默认会注册，所以外壳用 `DeviceEventFilter::Always` 关掉设备事件，否则流界窗口在前台时键盘到不了远端。

## 5. 键盘

- 网络上传输 **USB HID 键码**（Usage Page 0x07），与系统和键盘布局无关。平台层负责 macOS 虚拟键码 / Windows 扫描码 ↔ HID 的双向转换。
- 传 **物理按键** 而不是字符，目标电脑的输入法照常处理按键，因此中文、日文等输入法体验保持不变。
- 组合键：修饰键作为普通按键按下/抬起，天然支持任意组合。修饰键由 **目标侧** 换算（`engine::map_key`）：
  - Mac 控制 Windows：⌘ ↔ Ctrl 互换，在 Mac 上按 ⌘C，Windows 收到 Ctrl+C。
  - PC 键盘控制 Mac：按 Mac 上的设置「Windows 键盘的修饰键」（`Settings::win_keys`，`flow-core::keys::WinToMacKeys`）——Windows 习惯（默认，Ctrl → ⌘、Win → ⌃，与旧版本一致）/ Mac 键位（空格旁的 Alt → ⌘、Win → ⌥）/ 直通（Win → ⌘）/ 自定义（Ctrl、Win、Alt 各自指定 ⌃⌥⌘ 之一，左右键分别对应）。因为是目标侧换算，这项设置只在 Mac 的设置页出现；不改协议，对方版本无要求。引擎把当前对应关系存一份在单独的锁里，改设置立即生效；注入时与暂停状态协调，保证暂停完成后不再注入新输入。已经按着的键按按下时的换算抬起，不会卡键。
- Mac 被控制时注入的事件只带对方按下的修饰键（不混入本机键盘的状态），小键盘 / Fn 标志按键位查表加上（方向键、功能键、小键盘在真实键盘上固定带着；不从系统创建的事件里读，那里面会混进本机当前的 Fn 状态）；Caps Lock 由注入器自己记状态并带上大写锁定标志（注入的 Caps Lock 按键不会改变系统的大写锁定）。Windows 上 Pause 和 Num Lock 按虚拟键码注入（它们在钩子里报告的扫描码和硬件扫描码语义相反）。
- 长按：注入的按键不会被目标系统自动连发，因此转发源设备系统产生的连发事件（`repeat = true`）。
- **按键状态跟踪**（`flow-core::keys::PressedState`）：源和目标两侧都记录"已按下但未抬起"的键和鼠标按钮。切换离开、断网、心跳超时、休眠时，目标侧自动释放全部按键，源侧恢复本机输入——避免"卡键"。
- **大写锁定同步**：两边的大写锁定各记各的，切过去时状态不同的话，之后每按一次 Caps Lock 两边一起翻转，就一直相反。所以控制方在开始控制时、以及控制期间状态变化时，把本机大写锁定的状态告诉对方（平台层报 `CapturedEvent::CapsLock`），被控制方对齐过去（`InputInjector::set_caps_lock`）。不改协议：借用按键消息，键码用 HID 里没有的两个保留值（`KeyCode::CAPS_STATE_ON` / `CAPS_STATE_OFF`），只发"抬起"；不认识它的旧版本在键码表里查不到，直接忽略。各系统的做法：
  - 控制方：macOS 和 Windows 由控制器在每次切过去时直接查系统的状态（`flow_platform::caps_lock_on`）；Linux 的 X11（查指针掩码里的锁定位）和 Hyprland / Sway（拿到键盘焦点时合成器报的修饰键状态）由捕获上报，控制期间变了还会再报。GNOME / KDE 的 Wayland 做控制方时还不上报。
  - 被控制方：macOS 改注入器自己记的状态；Windows、Linux 的 X11 和 Hyprland / Sway 是状态不同就按一下 Caps Lock。GNOME / KDE 的 Wayland 做被控制方时还不对齐。
  - Windows 的查询用 `GetKeyState`，仅通过交叉编译检查，待真机验证。Windows 做控制方时，控制期间按下的 Caps Lock 被钩子拦截、不改本机状态，所以下次再切过去时对方会被对齐回 Windows 这边的状态。
- **快捷键与快捷键映射**（`flow-core::hotkeys`，设置里的 `Settings::hotkeys`）：快捷键是"手边这台电脑"的——只有物理键盘所在的电脑看得到按键，所以各台电脑各设各的，由控制器（`input::Controller`）在捕获回调里匹配。一组键 = 修饰键位掩码 + 一个 HID 主键，修饰键按"恰好相等"匹配（Ctrl+Alt+S 和 Ctrl+Alt+Shift+S 是两个快捷键）；触发键必须带 Ctrl、Alt 或 ⌘ / Win 之一，功能键（F1–F20、Print Screen、Scroll Lock、Pause）可以单独用（F21–F24 各系统的键码表里没有，不收）。保存前由 `Hotkeys::sanitized` 去掉不合法和重复的；设备被移除时指向它的一并删掉。三类动作：
  - 切到左 / 右相邻的电脑：默认 Ctrl+Alt+←/→，可以改、可以关。
  - 切到指定的电脑（包括回到本机）：`Controller::switch_to_device`，进入目标面积最大的那块屏幕的中央。
  - **快捷键映射**（用户需求，类似 Synergy 的 hotkey）：按下一组键，让指定的电脑收到另一组键，键鼠不用切过去。控制方发 `Message::KeyStroke { keys }`（0.2.4 新增，修饰键在前），被控制方不需要先收到 `Enter`：依次按下、反序抬起，修饰键照常按第 5 节的规则换算。如果正在控制它的设备手上还按着修饰键（触发映射用的 Ctrl、Alt 多半已经发过去了），被控制方先把它们抬起、按完再按回去（`hotkeys::tap_sequence`），否则对方收到的是 Ctrl+Alt+S 而不是 S。发来的按键也算"有人在用"，屏幕熄着会点亮。对方暂停了共享时不理会；锁定在本机不影响发送（没有把键鼠切出去）。看不到全局键盘的桌面（Wayland）上键鼠在本机时触发键按了没反应，改用命令 `flowacross --mapping <序号>`（`Engine::mapping_command`，序号是设置里映射的次序，从 1 开始）在桌面自己的快捷键设置里绑定，和 `--switch` 一样由已经在运行的流界执行。
  - 动作做不成时（没有那台电脑、没连着、被暂停、对方版本太旧）不算快捷键，按键照常交给原来的去处，和以前"右边没有电脑时 Ctrl+Alt+→ 照常放行"一致。触发键的连发和抬起都拦截。
  - 设置页录制快捷键时，按键是从网页的键盘事件（`KeyboardEvent.code`，物理键位）换算成 HID 的（`app/src/keys.ts`）；录制期间界面通知引擎暂停响应快捷键（`set_hotkeys_suspended`），否则刚按下的组合键会直接把键鼠切走。
  - Wayland 上键鼠在本机时看不到键盘（`Limits::local_hotkey`），这些快捷键只有在键鼠已经切到别的电脑之后才起作用。
- **从菜单切到指定设备**（托盘 / 菜单栏的「把键鼠切到」、设备详情里的按钮，`Engine::switch_to`）：键鼠在别的电脑上、鼠标又不方便推过去时用。点菜单的这台电脑如果就是键鼠所在的电脑，直接让控制器切过去；如果它正被别的电脑控制（用户是用那台电脑的键鼠点的菜单），键鼠不归它管，就发 `Message::SwitchTo { device }`（0.2.4 新增）请控制方来切，`device` 是控制方自己时表示回到它本机。控制方只在自己的键鼠确实在请求方那边时才理会，否则任何一台已配对的电脑都能随时把别人的键鼠拽走。没有键鼠捕获（缺权限）时不切：光标会被锁住、按键却到不了对方。GNOME / KDE 的 Wayland 上本机是键鼠所在的电脑时也不切（只有光标撞到屏幕边的屏障，合成器才肯交出键鼠，`Limits::commanded_switch`）；Sway、Hyprland 上可以（见第 12 节）。按钮和菜单项能不能点（`DeviceView::can_switch`）和真去切时的检查是同一个函数（`Engine::switch_blocker`）。托盘子菜单的内容随设备状态在主线程上重建，内容没变时不动；「暂停共享」「锁定在本机」两项也只在变化时才改（改菜单项要等主线程，而状态是在会话收消息的循环里推送的）。
- **用命令切换**（`flowacross --switch <目标>`，`Engine::switch_command`）：再次运行流界并带上这个参数，单实例插件把它转给已经在运行的那个，由它执行，窗口不动。目标可以是 `left` / `right`（布局里左、右最近的一台）、`home`（回到这台电脑）、设备名称或设备 ID 的前几位。给看不到全局键盘的桌面用：在 Sway、Hyprland 里把合成器的快捷键绑到这条命令，就有了"本机快捷键切换"；也方便脚本和宏按键。流界没在运行时带这个参数启动，会照常启动但不弹窗口。失败的原因通过界面提示给出（窗口隐藏时看不到，日志里有）。
- **物理按住的修饰键**（`Controller::mods_down`）：快捷键匹配和「按住修饰键才切换」看的是控制器自己记的"手上按着哪些修饰键"，不从按键路由里算。键鼠从一台远端切走时，路由会把在那台远端按下的键全部释放并忘掉，而手其实还按着；以前不松开 Ctrl+Alt 接着按第二个快捷键会失效，主键还会打到新的那台电脑上。
- **滚轮**：消息里的单位是 1/120 格，一格对应 3 行（Windows 和多数 Linux 桌面的默认值）。macOS 的滚动事件以"行"为单位，捕获和注入都按 3 行 = 一格换算（`LINES_PER_NOTCH`）；非整格的注入按像素发，一格约 30 像素。早先两头都按 1 行 = 一格：Windows 控制 Mac 时一格只滚 1 行，翻网页要滚半天；Mac 控制 Windows 时滚 1 行对方就滚一整格，一直偏快。设置里的「滚轮速度」（`Settings::wheel_speed`，百分比）由控制方在发出滚动之前换算，除不尽的部分攒到下一次；在手边这台电脑上设置，对所有被控制的电脑生效，对方不需要升级。
- Windows 的低级键盘钩子报告右 Shift 时带着扩展键标记，而它的扫描码（0x36）本身不带前缀；`keymap::from_win` 对它忽略这个标记，否则查不到键码，右 Shift 传不到对方、还会漏给本机（真机发现）。
- 已知系统限制：Windows 的 Ctrl+Alt+Del、UAC 安全桌面无法注入；向管理员权限窗口注入需要流界本身以管理员运行。这几种情况系统不报错，流界察觉不到，界面上没有提示（发布仓库的 README「已知限制」里有说明）。注入器建不起来、或授权没了（Linux 的 GNOME / KDE）时会提示一次，见第 9 节和第 12 节。

## 6. 网络、发现与配对

- **发现**：mDNS 服务 `_flowacross._udp.local.`，TXT 记录含设备 ID（证书指纹的完整十六进制）、名称、系统；协议版本在握手的 `Hello` 里核对。同时记住的服务名最多 256 个，超出的不理会。
- **身份**：每台设备首次启动生成一对长期密钥和自签名证书（保存在应用数据目录；macOS 上私钥文件权限 0600，已有文件权限更宽时读取后收紧；Windows 上依靠用户数据目录的访问控制），设备 ID = 证书 DER 的 SHA-256 指纹。身份文件存在但读不出来（权限、被安全软件占用）时启动报错，不重新生成——重新生成会换掉设备 ID，所有配对失效。
- **TLS**：QUIC 双向证书认证。TLS 层只校验握手签名（证明对方持有私钥），证书是否可信由应用层按指纹判断。通过 mDNS 发现的地址连接后，必须核对证书指纹就是要连的设备。
- **连接地址的顺序**（`diagnose::order_addrs`）：和本机在同一个子网的地址先试，去掉自动分配的 169.254.x.x，最多试 8 个。对方常常同时广播着 VPN、虚拟机、容器网卡的地址，逐个去连的话每个都要等到超时，而自动重连总共只有约 30 秒。
- **发现的数据不可信**：mDNS 可以被局域网里任何人伪造。TXT 里的设备 ID 必须是 64 位小写十六进制（`DeviceId::is_well_formed`），否则丢弃；名称一律经 `protocol::clean_name` 去掉控制字符、截到 64 个字符（`Hello`、`Profile` 里的名称同样处理）。日志里截断 ID 用 `DeviceId::short`（按字符截断，不会 panic）。
- **配对**（`flow-core::pairing`，0.1.7 起）：带承诺的 6 位配对码。发起方先发随机数 `nI` 的承诺 `PairCommit(H(fpI, nI))`，响应方回 `PairNonce(nR)`，发起方再公开 `PairNonce(nI)`，响应方核对承诺；配对码 = H(fpI, fpR, nI, nR, TLS 通道绑定值)。双方界面都显示配对码，用户核对一致并在两边都点"确认"后，互相保存对方指纹为可信设备。只用两个指纹算码时，中间人可以反复换证书离线凑出两边相同的码（0.1.6 及以前的问题）；有了承诺，每边的码都取决于中间人出牌时还不知道的随机数，每次尝试只有百万分之一的机会，通道绑定值让码只对这一条 TLS 连接成立。对方版本低于 0.1.7（`SECURE_SINCE`）时不配对，提示两边都更新；已经配对过的旧版本设备照常连接。别人发起的配对请求每分钟最多弹 3 次。
- **未认证连接的限制**：同时处在握手 / 配对阶段的入站连接最多 8 个，超出的直接拒绝；进入会话（双方互信）之前单帧最大 16 KB（`HANDSHAKE_FRAME_LEN`），之后放开到 8 MB。QUIC 层也收紧了（`tls::transport`）：不接受单向流，双向流最多 16 条，整条连接没被读走的数据最多 8 MB——quinn 的默认值是各 100 条流、每条 1.25 MB、总量不限，没通过认证的连接就能让本机缓冲几百 MB。日志只保留最近 14 天。
- **对端上报的数据要先过一遍**：显示器列表（`protocol::sane_displays`：位置、尺寸、缩放必须是有限且合理的数，最多 16 块；NaN 写进 config.json 会变成 `null`，下次启动整个配置读不出来）、文件清单里的名称和出错原因（截短、去控制字符）、剪贴板消息的来源（必须是发来消息的设备自己）、布局（见第 3 节）。握手完成时设备已经被用户移除的，不建会话；不在配置里的设备发来的输入一律不接受。
- **握手**：发起方先发 `Hello`（含 `trusts_you`：是否已信任对方）。双方互相信任 → 直接建立会话并交换显示器信息；否则只有用户主动发起时才进入配对（`PairRequest` → 双方各自 `PairConfirm`），自动重连遇到对方不再信任、或协议版本不兼容时提示一次并停止自动重连（改为手动连接），不随每次重试反复提示；未认证的陌生连接版本不对时不提示。
- **连不上时说清原因**（`flow-core::diagnose`）：每次连接失败（自动重连和手动连接、配对都算）引擎收集几样事实——现在还能不能用 mDNS 发现它、它的地址和本机各网卡的地址与子网掩码（`flow_net::local_networks`）、是超时还是当场被拒、对方的系统——换成最可能的原因和按顺序排查的步骤，记在 `State::failures` 里，显示在设备详情和「添加设备」窗口里那台电脑下面（`DeviceView::problem` / `NearbyView::problem`），连上后清掉；用户自己点的连接另外弹一次提示。判断顺序：本机没有网 → 两边的 IPv4 地址不在同一个子网（把两个地址都写出来）→ 发现得了却连不上（防火墙、VPN / 代理的虚拟网卡，按对方的系统写出在哪里放行）→ 发现不了（没开流界、睡眠、访客网络 / AP 隔离、Mac 的本地网络权限）。身份不符、握手没走完、协议版本不兼容各有自己的说明，版本不兼容时带上两边的版本号。这些是按现象推断的，不保证每次都对，所以每条都给出不止一步。
- **设备为什么离线**：会话结束时看连接的关闭原因——对方的流界正常退出（关闭端点时带着 `shutdown`）显示「已经退出」，对方突然没了回应（QUIC 空闲超时）显示「可能睡眠了、断网了或关机了，醒来后会自动连回来」，记在 `State::gone` 里，和上面的诊断一起显示。对方不见之后，局域网里它的 mDNS 记录还会留一阵（睡眠的机器来不及说"我走了"，最长两分钟才过期），这期间的重连会被诊断成"看得到却连不上：防火墙"；已经知道它是怎么不见的，就不拿这个误判盖掉真正的原因。流界退出时会停掉 mDNS（发一条"我走了"），别的电脑马上就发现不了它。
- **重连**：每 2 秒检查一次离线的已配对设备，地址优先用 mDNS 最新结果，其次用上次成功连接的地址；指数退避 2s→30s，mDNS 重新发现设备时立即重试（不重置次数）。设备离线后最多自动重试 5 次（约 30 秒），仍失败就停止，标记为「已断开」等用户手动连接；对方的流界启动时会主动连过来，手动连接失败也不恢复自动重试。设备 ID 较小的一方先连，较大的一方晚 6 秒；万一两边同时连上，双方都保留"发起方 ID 较小"的那条连接，结果一致。
- **移除**：一方移除设备时发送 `Bye(Removed)`，对方收到后也删除可信记录。
- **通道**：
  - 控制流（可靠有序）：握手、进入/离开、按键、鼠标按钮、滚轮、心跳、剪贴板文本、文件清单。
  - 数据报（不可靠）：鼠标绝对坐标，丢一个无所谓，下一个会覆盖。
  - 传文件的流（可靠，按需新开）：复制的文件内容，每次传输在同一条连接上另开一条双向流（`flow-net::link::open_stream`），大文件不会阻塞控制流里的键鼠消息。
- **心跳**：进入远程控制后每 500ms 一次；目标侧 3s 未收到任何消息即释放全部按键并结束远程会话。0.1.7 起目标侧对每个心跳回 `HeartbeatAck`，控制方 1.5 秒收不到回执就认为断网：释放远端按键、恢复本机输入并提示，不用等 QUIC 的 8 秒空闲超时。对方版本低于 0.1.7 时不回执，仍按 QUIC 超时处理。

## 7. 剪贴板（文本、文件与图片）

系统剪贴板没有跨平台的变化通知，引擎每 0.5 秒读一次变化计数（macOS `changeCount`，Windows `GetClipboardSequenceNumber`），有新文本就通过 `ClipboardSync` 发给已连接且未暂停的设备；写入远端内容后记下新的计数，避免回传。

- 纯文本超过 4 MB 的不同步；图片走文件的传输通道（见下面「复制图片」）；富文本等其他格式暂不同步。
- 每条内容带 `(来源设备, 序号)`，写入远端剪贴板后不会再被回传，避免回环。对方重启后序号从 1 重新开始，所以每次和它建立会话时忘掉之前记下的最大序号（`ClipboardSync::forget`），否则对方更新、重启后的前若干次复制会被当成旧消息丢掉。
- 可以全局关闭，也可以按设备关闭。

### 跨设备复制文件

用法和文字一样：在 Finder / 资源管理器里复制文件，把键鼠切到另一台，粘贴。

1. **只发清单**：剪贴板变化时先看是不是文件（macOS 读 `public.file-url`，Windows 读 `CF_HDROP`）。是文件就在后台线程遍历一遍，算出文件数和总大小，发 `FileOffer`（编号、顶层名称、文件数、字节数）给支持的设备，不发内容。剪贴板换成别的内容时发一个空清单撤回。新连上的设备会补发当前清单；复制时没有能收文件的设备连着，就先只记下路径，等设备连上再整理清单发过去。
2. **什么时候取**（`flow-core::files::OfferBook`）：接收方只记最新的一份清单。键鼠来到本机时（开始被控制，或控制远端后回到本机）自动去取；清单在键鼠来到后 2 秒内才到、或本机正被控制时收到，也自动去取。超过 1 GB 的不自动取，侧栏显示「接收」按钮；单独暂停某台设备时保留它已有的清单等手动接收，全局暂停共享则清空清单。实际收到的字节数超过清单声明的 1.25 倍 + 64 MB 就中止（`transfer::receive_limit`），对方不能靠少报大小绕过这个上限。本机又复制了别的、或收到其他设备的文字时，旧清单作废。
3. **传输**：接收方在同一条 QUIC 连接上新开一条流，发 `FileRequest { id }`；发送方重新遍历文件，依次发 `FileEntry`（`/` 分隔的相对路径、大小、是否目录）和 `FileChunk`（每块最多 256 KB，按字节串编码），最后 `FileEnd`；出错发 `FileError`（原因直接显示给用户）。编号对不上（发送方剪贴板已经换了）也回 `FileError`。
4. **落盘**：先写进接收文件夹（下载文件夹里的「流界」）中的临时目录 `.flowacross-*`，全部收完再移出来，重名时改成「报告 (1).pdf」。中途失败或取消就删掉整个临时目录（移出来到一半失败时，已经移出的也撤掉）；启动时清理异常退出留下的。一次复制的多项重名时（来自不同文件夹）后一个改名。`flow-core::files::Incoming` 校验消息顺序和大小，路径里的绝对路径、`..`、Windows 不允许的字符和保留名（CON、NUL…）一律拒绝或替换。目录里的符号链接和 `.DS_Store`、`Thumbs.db` 这类系统文件不传。
5. **写入剪贴板**：收完后把文件路径写入本机剪贴板（Windows 另写 `Preferred DropEffect = 复制`，粘贴时不会当成剪切），然后提示「可以直接粘贴」。如果接收期间用户又复制了别的（剪贴板的"代"变了），就不覆盖剪贴板，只提示文件保存在哪里。
6. **取消与进度**：一次只接收一份，新的取代还没收完的旧的。侧栏「文件」面板显示进度（最多每 200ms 推一次），两边都能取消；接收方取消后发送方的写入立即失败并停止。
7. **兼容**：`FileOffer` 等是协议里的新消息，旧版本解析不了会断开连接，所以只发给版本 ≥ 0.1.5（`FILE_TRANSFER_SINCE`）的设备；不按"版本号相同"放行，因为开发版本和已发布的同号版本协议不同。对旧版本照旧只发文字（Finder 复制文件时附带的文件名）。两台电脑联调开发版本前，先把版本号改到 ≥ 0.1.5。
8. **开关**：设置里「复制文件」跟随「共享剪贴板」，可以单独关掉；暂停共享、暂停某台设备时也不收发。

### 复制图片

截图直接进剪贴板、在浏览器或看图软件里复制图片时，剪贴板里只有图片数据，没有文字也没有文件路径。这类内容复用上面的文件通道，只是两头各多一步：

1. **发送方**：剪贴板变化后既不是文件、也没有文字，并且连着能收文件的设备时，在后台线程读图片并统一转成 PNG（macOS 读 `public.png`，没有就把 `public.tiff` 转成 PNG；Windows 读约定俗成的 `PNG` 格式，没有就把 `CF_DIB` 转成 PNG，`flow-platform::dib`）。存成临时文件 `<流界的数据目录>/clipboard-image/<代>/剪贴板图片.png`（只留最新一张；0.2.3 及更早放在系统临时目录的 `flowacross-clipboard` 下，Linux 上 /tmp 所有用户共用，别的本机用户能读到，所以挪进了数据目录），然后和复制文件一样发清单，只是清单标着 `image`。有文字时不看图片：表格、文档软件复制文字会顺带放一张渲染图。读取和转换另开一个剪贴板访问，不占引擎的锁。
2. **协议**：`FileOffer.image` 不上网络（`#[serde(skip)]`），图片清单用单独的消息 `ImageOffer`（`FileOffer::into_message` / `from_message`），只发给版本 ≥ 0.2.0（`IMAGE_SINCE`）的设备；更旧的设备收到的是普通 `FileOffer`，粘贴出来是一个 PNG 文件。撤回仍用 `FileOffer`。两台电脑联调开发版本前，先把版本号改到 ≥ 0.2.0，否则两边都按文件处理。
3. **接收方**：取回的过程和文件完全一样。收完后把图片本身写入剪贴板（macOS 写 `public.png`；Windows 同时写 `CF_DIB` 和 `PNG`，透明处在 `CF_DIB` 里垫白），并删掉收到的文件，不在接收文件夹里攒截图；提示「可以直接粘贴」。Windows 上 PNG 解成位图在持锁之前做（`flow_platform::ClipboardImage::from_png`）。写不进去（接收期间用户又复制了别的、内容不是 PNG）时保留文件并提示保存位置。
4. **限制**：PNG 超过 64 MB（`MAX_IMAGE_BYTES`）不同步并提示；复制图片时没有设备连着，之后连上的设备不会补发（文件会补发），重新复制即可；Windows 上只认 24 / 32 位未压缩位图。开关跟随「复制文件」。

## 9. 失败处理原则

任何异常（断网、对端休眠、注入失败、心跳超时、权限被撤销）都遵循同一顺序：

1. 目标侧释放全部按键和鼠标按钮；
2. 源侧立即停止拦截，本机恢复可用，光标回到离开时的边缘（断网时靠心跳回执在 1.5 秒内发现，见第 6 节）；
3. 界面显示明确原因 + 处理建议（如"对方电脑已休眠，唤醒后会自动重连"）。提示是主界面里的浮层，窗口隐藏在托盘时看不到（走系统通知还没做）；设备连不上的原因另外常驻在设备详情里。

读不到本机剪贴板时（桌面的剪贴板服务没起来、GNOME 上没同意远程桌面的授权）提示一次，之后每半分钟再试；以前是静默放弃到下次启动，设置里「共享剪贴板」却还显示开着。

**配置文件损坏**（`config::Config::load`）：`config.json` 解析不了时，先改名备份为 `config.json.bad-<时间戳>`，再用默认配置继续运行，主界面一直显示原因和备份位置，直到用户点「知道了」。连改名都失败（比如没有权限）时，这次运行不写配置，避免覆盖原文件。以前是静默用默认配置，下一次保存就把所有配对覆盖掉了。

### 系统睡眠与锁屏

- **睡眠后醒来**（`flow-core::diagnose::ResumeDetector`）：不接各系统的睡眠通知，用一个各系统通用的办法：维护循环每 2 秒跑一次，两次之间墙上时钟却过去了 15 秒以上，说明整台电脑停过。这时对方那边的连接早已超时（QUIC 空闲超时 8 秒），本机手里的连接也都没用了。`Engine::on_resume`：先把键鼠还给本机、释放按键，关掉旧连接（不等它们自己超时），清掉"自动重连已停止"的标记并马上重连；睡前有设备连着才提示「刚从睡眠中醒来，正在重新连接」，之后 45 秒内这些设备显示成「连接中」，不在两次重试之间来回跳。睡前就没连着的设备也顺带再试一轮（可能是带着笔记本回到了有它的网络），但这一轮试不通时不再弹「已暂停自动重试」。系统时钟被大幅调快时会误判一次，后果只是重连一次。睡着的那台不会通知对方：对方看到的是"突然没了回应"（见第 6 节）。
- **锁屏**（`flow_platform::power::screen_locked`）：每台电脑每 6 秒查一次自己是不是停在锁屏界面（macOS 查会话字典的 `CGSSessionScreenIsLocked`，Windows 查终端服务会话的锁定标志，Linux 读 logind 会话的 `LockedHint`；只在有设备连着时查，连续三次查不到就不再查并告诉对方"没锁"，免得停在最后一次的结果上），变化时发 `Message::Status { locked }`（0.2.4 新增）给认得它的设备，会话建立时锁着也发一次。对方据此在设备上标「已锁屏」，把键鼠切过去时提示一次"需要在那台电脑上解锁"（解锁后再锁屏会再提示）。macOS 和 Windows 的锁屏界面不接受注入的按键，这是系统限制；Linux 上通常能直接输入密码，提示里按对方的系统区分。Sway、Hyprland 上要看锁屏程序是不是通过 logind 上锁的，没设置 `LockedHint` 的话一直显示"没锁"。锁着屏也不阻止切过去（至少能点亮屏幕、看到它）。

### 屏幕熄灭（`flow_platform::power`）

被控制的电脑长时间没人用，屏幕会自动熄灭。这时要保证别的电脑仍然切得过来，并且能把它点亮：

- **熄屏时保留布局**（`flow_core::protocol::settle_displays`）：macOS 不把休眠的显示器算作可用，有的外接显示器熄屏后还会断开信号，定时枚举到的屏幕列表会变少甚至变空。照实发出去，别的电脑的布局里就没有这台电脑了，键鼠切不过来。所以熄屏期间（macOS 查 `CGDisplayIsAsleep`，Linux 的 X11 查 DPMS；只在列表变了的时候才查）和列表为空时沿用上一份；接收方收到空列表也沿用原来的（旧版本会发空列表）。Windows 和 Wayland 查不到熄屏状态，只有"列表为空"这一条生效。
- **远端键鼠算作用户操作**（`power::input_activity`）：macOS 不把 `CGEventPost` 注入的事件算作用户操作，屏幕熄着不会亮，亮着也照样到时间熄灭。所以别的电脑的键鼠进来（`Enter`）和之后的每次移动、点击、滚动、按键，被控制方都向系统声明"有人在用"（`IOPMAssertionDeclareUserActivity`），最多每 2 秒一次；心跳和大写锁定状态这类通知不算。键鼠一直停在这台电脑上、屏幕中途熄了，动一下鼠标也能点亮。Windows 的 `SendInput`、X11 的 XTest、Wayland 的虚拟指针在系统看来就是输入设备，本身会点亮屏幕，这一步无操作。
- **唤醒屏幕**（`power::wake_display`）：键鼠切不过去的时候，控制方在设备详情里点「唤醒屏幕」，发一条 `Message::Wake`（0.2.3 新增，只发给认得它的版本；对方暂停了共享时不理会）。macOS 同上，Windows 注入一次来回 1 像素的鼠标移动并重置熄屏计时，Linux 的 X11 重置屏幕保护并强制打开 DPMS。Wayland 没有通用接口：Sway、Hyprland 用合成器的屏幕电源协议（wlr-output-power-management，`linux_wl_power.rs`）直接把所有屏幕打开，不动鼠标；GNOME、KDE 没有这类接口，改为把鼠标移到主屏中间，由合成器当作用户操作来点亮（本机正在控制别的电脑时不动鼠标）。
- **保持屏幕常亮**（设置 › 通用，默认关，`power::set_keep_awake`）：开着且有设备连着时不让本机屏幕自动熄灭，不影响手动锁屏。macOS 用电源断言 `PreventUserIdleDisplaySleep`，Windows 用专门的线程持有 `SetThreadExecutionState`，Linux 向桌面的 `org.freedesktop.ScreenSaver` 登记（GNOME、KDE、Xfce、hypridle 等提供；实际登记失败时每次打开开关只提示一次）。启动时先探测一次做不做得到（`power::keep_awake_problem`，Linux 上看会话总线有没有这个服务，正在运行或可以按需启动都算）：做不到时设置里的开关禁用并在旁边写明原因，之后每 30 秒重查，查到能用了就恢复（开机自启时流界可能比桌面的服务先起来）。
- **做不到的**：屏幕点亮后如果停在锁屏界面，密码要在那台电脑上自己输。macOS 锁屏时开启安全输入，注入的键盘事件进不了密码框，这是系统限制。

## 10. 打包与自动更新

- **打包**：推送 `v*` 标签后由 GitHub Actions（`release.yml`）用 tauri-action 打包 Windows NSIS 安装包、macOS 通用版（.dmg + `.app.tar.gz`）和 Linux 安装包（deb、AppImage，以及由 deb 重新打包的 Arch 包 pkg.tar.zst；三个都用更新私钥单独签名），发布到公开仓库 `Hearion/FlowAcross-releases`。安装包一直发布在这个单独的仓库里（源码仓库当初是私有的，App 无法匿名下载其中的文件）；源码仓库现在已公开，仍沿用它，已安装的流界的更新地址保持不变。
- **更新清单**：每次发布带一个 `latest.json`（版本号、更新说明、各平台下载地址和签名）。
- **阿里云 OSS**：GitHub 在国内下载慢、时常连不上，所以发版时在正式发布之前，由 `scripts/mirror-to-oss.mjs` 把这次的全部文件复制到 OSS 存储桶 `bapihou-app-release` 的 `FlowAcross/` 目录（工作流里的 `OSS_PREFIX`；这个存储桶还放别的软件）：`releases/<标签>/` 下按原文件名放一份（内容不再改动）；正式版还会更新 `latest/`（不带版本号的固定文件名，给官网下载按钮用，浏览器保存时仍带版本号）和根目录的 `latest.json`（下载地址改指 OSS 的版本目录）。顺序是先传文件、最后换清单，OSS 失败时 GitHub 上也不发布，两边的最新版本保持一致。已发布的版本可以用「补传到阿里云 OSS」工作流（`mirror-oss.yml`）手动补传，它不允许把 `latest.json` 换回旧版本。
- **App 读哪份清单**：`tauri.conf.json` 的 `endpoints` 依次是 OSS 的 `https://dl.bapihou.com/FlowAcross/latest.json`（下载域名 dl.bapihou.com 绑定在存储桶上，HTTPS 证书过期时请求失败，会自动退到下一个）和发布仓库的 `releases/latest/download/latest.json`。插件按顺序尝试，前一个连不上或出错才读下一个；读到哪份清单，就从那份清单写的地址下载。0.2.3 及更早的版本只认 GitHub 的地址，要先从 GitHub 升到下一个版本，之后才走 OSS。
- **Linux 的应用内更新**（0.2.4 起）：三种安装包各有各的装法，应用启动时先认出自己是怎么装上的（`updater::install_kind`）：设了 `APPIMAGE` 环境变量的是 AppImage；否则问 `dpkg-query -S` 和 `pacman -Qo` 程序文件归谁管；都不认的（自己编译的、别人重新打包的）只提示有新版本并给「打开下载页」，不自动安装。不看程序里记的打包类型：Arch 包是把 deb 里的文件原样重新打包的，程序以为自己是 deb 装的。
  - 清单里的名字：`linux-x86_64-appimage`、`linux-x86_64-dpkg`、`linux-x86_64-pacman`，应用用 `target()` 指定找哪一项。后两个是流界自己起的名字，故意不用插件默认会找的 `linux-x86_64-deb` 和 `linux-x86_64`：0.2.3 及更早的 Linux 版不会分辨 Arch，清单里一旦有那两项，装在 Arch 上的旧版本就会去下 deb、跑 `dpkg -i`，然后报安装失败。旧的 AppImage 只找 `-appimage`，能正常收到更新；旧的 deb / Arch 版本要手动升到 0.2.4，之后才走应用内更新。
  - 安装：AppImage 由插件直接替换文件。deb 和 Arch 包由插件下载并验签（和其他平台同一把公钥），再交给系统的包管理器：`pkexec /bin/sh -c …` 弹出系统的授权窗口，安装包从流界的内存经标准输入交给 root，由 root 写进只有 root 能进的临时目录（`mktemp -d /var/tmp/…`）后 `dpkg -i` / `pacman -U --noconfirm`。不把验过签名的包先放到用户可写的临时文件再让 root 去装：授权窗口停留期间同一用户下的其他进程可以把文件换掉（和 macOS 低延迟模式的安装是同一个考虑）。
  - 顺序和其他平台相反：**先装好，再关引擎、重新打开**。授权可能被取消、包管理器可能正忙，装不成时流界照常运行，只提示原因和手动安装的办法；其他平台的安装程序会直接结束当前进程，所以是先关引擎再装。
  - `pkexec` 要有 polkit 认证代理在运行才会弹窗：GNOME、KDE 自带，Sway、Hyprland 上要用户自己启动一个，没有时提示原因并指向下载页。
  - 发版时 Linux 的打包任务不写 `latest.json`（和 Windows、macOS 的任务同时改会互相覆盖，tauri-action 写的还是上面那两个不能用的名字），只用 `tauri signer sign` 给三个安装包签名并上传 `.sig`；三个打包任务都结束后，发布任务用 `scripts/add-linux-updates.mjs` 把它们写进 `latest.json`，再复制到 OSS。
  - 验证情况：安装方式的判断、清单里的名字、root 安装脚本（用普通 shell 跑过，包的内容原样到了"安装命令"手里）、往清单里加条目的脚本都有测试；**整条链路（发版 → 清单 → 下载验签 → `pkexec` 安装 → 重新打开）没有在真的 Linux 桌面上跑过**，要等第一个带 Linux 更新包的版本发布之后，再用它的下一个版本验证。
- **签名**：更新包用 minisign 私钥签名（私钥只在 GitHub Secrets 和开发者本机），公钥写在 `tauri.conf.json`，App 下载后先验签再安装。本地打包不生成更新包，不需要私钥（CI 打包前才打开 `createUpdaterArtifacts`）。
- **App 端**（`app/src-tauri/src/updater.rs`，`tauri-plugin-updater`）：发布版启动 15 秒后、之后每 6 小时检查一次（设置里可关），只提示不自动安装。用户确认后：下载（引擎照常工作，失败不影响使用）→ `Engine::shutdown()` 释放远端按键、恢复本机输入、断开连接（之后重连、键鼠捕获、剪贴板等后台循环全部停止，可重复调用）→ 安装 → 重新打开。安装失败时提示原因并提供「重新打开流界」。
- **macOS 授权**：系统按代码签名记住辅助功能/输入监控授权。CI 用固定证书（`APPLE_CERTIFICATE`）签名，更新后授权保持有效；没有证书时退回 ad-hoc，每次更新都要重新授权。
- **测试版**：版本号带后缀的标签（如 `v0.2.2-beta.1`）发布成 Pre-release，不成为 latest，已安装的流界收不到更新提示。
- **测试版的构建配置**：发布构建三分之二的时间花在最后一步"整体优化"上（全量 LTO 加单个代码生成单元，基本是单线程；日志会停在最后一个依赖 `gethostname` 那一行，其实是在编主程序）。测试版在发版流程里改用轻量 LTO 和 16 个代码生成单元（`CARGO_PROFILE_RELEASE_*` 环境变量），本机实测总耗时减半，二进制大约 3.6 MB；正式版不变。
- 发版步骤和一次性配置见 `docs/release.md`。

### 开机启动与单实例

外壳代码在 `app/src-tauri/src/startup.rs`。

- **单实例**（`tauri-plugin-single-instance`，最先注册）：再次打开流界时，第二个进程在初始化前就退出（不会抢端口、不会装键盘钩子），已在运行的流界把窗口显示到前台。Windows 用命名互斥量 + 隐藏窗口传参，macOS 用 `/tmp` 下的 Unix socket。调试用的 `FLOWACROSS_PROFILE` 实例不注册这个插件，仍可同机多开。
- **开机启动**（`tauri-plugin-autostart`）：Windows 写当前用户的 `Run` 注册表项（同时清掉任务管理器里的「已禁用」标记），macOS 写 `~/Library/LaunchAgents/FlowAcross.plist`。启动项带 `--autostart` 参数。开关状态不存配置文件，设置页每次（包括窗口回到前台时）都读系统里实际的注册状态；界面通过 `get_autostart` / `set_autostart` 两个命令调用，不直接开放插件自带的前端命令。
- **启动时隐藏窗口**：主窗口在 `tauri.conf.json` 里默认 `visible: false`，`setup` 末尾判断：带 `--autostart` 时只在托盘 / 菜单栏运行，否则显示窗口。
- **重新打开**：Tauri 和 Windows 安装程序重新打开流界时会沿用原来的启动参数，所以更新安装前、点「重新打开流界」前会在数据目录写一个一次性标记 `show-window-once`，下次启动看到它就照常显示窗口。「重新打开流界」是主线程上的同步命令，必须用 `request_restart()` 走正常退出流程，单实例锁才会在新进程启动前释放。

## 12. Linux

Linux 上有三套实现，启动时按桌面会话选一套（`linux_wl.rs` 的 `backend()`，只判断一次），入口和分发在 `linux.rs`：

| 会话 | 实现 | 文件 |
|---|---|---|
| X11 | XInput2 / XTest / RandR / X 选区（纯 Rust 的 x11rb，不链接 libxcb / libX11） | `linux.rs`、`linux_input.rs`、`linux_clipboard.rs`、`linux_glow.rs` |
| Wayland，合成器有 wlroots 的虚拟输入和 layer-shell 协议（Sway、Hyprland 等） | 虚拟指针 / 虚拟键盘、layer-shell、data-control（纯 Rust 的 wayland-client；xkbcommon 链接系统库） | `linux_wl.rs`、`linux_wlr_input.rs`、`linux_wl_clipboard.rs`、`linux_wl_glow.rs` |
| Wayland，其他合成器（GNOME、KDE） | xdg-desktop-portal（ashpd）+ libei 协议（纯 Rust 的 reis） | `linux_portal.rs`，剪贴板和浮光尽量复用上一行的 |

做不到的切换方式由 `flow_platform::limits()` 报告（按会话类型和有没有 layer-shell 判断）：引擎生成切换策略时忽略对应的设置（否则打开「按住修饰键才切换」就永远切不过去），并通过状态里的 `unsupported` 告诉界面，设置页和侧栏不显示这些选项。这是按现有实现判断的"做不到"，其中几项换个做法可以实现，见路线图。

Wayland 没有全局键鼠捕获和注入的统一接口，普通程序既看不到别的窗口的输入，也不知道光标在哪，所以两套 Wayland 实现和其他系统有几处共同的不同（下面各节细说）：只在通往别的电脑的屏幕边上感知"光标推到了边上"（引擎用 `flow_platform::set_switch_edges` 告知是哪些边，由 `flow_core::Layout::switch_edges` 算出）；没切到远端时看不到键盘，「按住修饰键才切换」和本机上的 Ctrl+Alt+←/→ 不起作用——Sway、Hyprland 上可以把合成器自己的快捷键绑到 `flowacross --switch left` / `right` 来代替（见第 5 节）。

### X11


- **显示器与缩放**（`linux.rs`）：RandR 1.5 的 monitor 列表，没有时把整个根窗口当一块屏幕；镜像的屏幕只算一块。X11 没有可靠的每屏缩放，桌面环境把整体缩放写在 `Xft.dpi`（GNOME、KDE 都是 96 × 缩放），所有屏幕共用这个值，逻辑坐标 = 像素 ÷ 缩放。
- **捕获**（`linux_input.rs`）：在根窗口上选 XInput2 原始事件。X11 不能逐个事件决定放行还是拦截，捕获回调返回的 `Verdict` 在这里不起作用，拦截靠抓取：`set_cursor_captured(true)` 时抓住主键盘和主指针（`XIGrabDevice`）并隐藏光标（XFixes），本机程序此后收不到输入，回到本机时放开并把光标放到跨回来的位置。抓取期间根窗口上的原始事件不再送给抓取者自己（实测），所以鼠标的原始事件写在抓取掩码里；键盘则改收抓取送来的普通按键事件，因为原始事件没有长按连发，而它带连发标记。同一次按键两种事件都到时按（键码、时间戳）去重。
  - 相对设备用原始事件里加速后的位移，贴着屏幕边继续推也有读数；绝对设备（虚拟机鼠标集成、数位板）用前后两次光标位置的差，贴边后推不出去，只能靠"碰到边"切换。
  - 别的程序正抓着键鼠时（打开着的菜单、全屏游戏）抓不到，这期间每来一个事件重试一次；重试成功之前本机仍能收到输入。
  - 在本机按 Ctrl+Alt+←/→ 切换时，这次按键本机的前台程序也会收到（抓取在按键之后才生效）。从远端切回来时不会。
- **注入**：XTest。注入的事件来自 X 服务的 XTEST 虚拟设备，捕获时按来源设备跳过（相当于另外两个系统的注入标记）；别的 XTest 工具（xdotool 等）注入的输入因此也不会转发到远端。长按连发交给本机 X 服务产生，对方发来的连发事件不注入。滚轮是按钮 4–7，一次点击一格，不足一格的先攒着。
- **键码**：evdev 键码（X 键码减 8）↔ HID，`keymap::from_linux` / `to_linux`。evdev 的主键区沿用 AT Set 1 扫描码，和 Windows 一列相同，只有扩展键、F13 以后、日文键等单独列表。修饰键换算和 Windows 相同（`map_key` 只区分 Mac 与非 Mac）。
- **剪贴板**（`linux_clipboard.rs`）：X11 的剪贴板不存数据，谁复制谁就是选区的所有者，别人粘贴时再向它要。所以有一个进程内唯一的后台服务（自己的连接、不可见窗口和事件线程）负责应答，`X11Clipboard` 只是句柄。读：`ConvertSelection`，文本和文件清单最多等 0.5 秒（引擎是持锁读的），图片 5 秒；写：保存各格式的数据并成为所有者。两个方向超过 1 MB 都按 ICCCM 的 `INCR` 分块。变化计数来自 XFixes 的所有者变化通知，自己写入时直接加一。格式：文本 `UTF8_STRING` / `text/plain;charset=utf-8`，文件 `text/uri-list` 加 `x-special/gnome-copied-files`，图片只认 `image/png`。流界退出后它写入的内容会消失（除非桌面有剪贴板管理器）。
- **边缘浮光**（`linux_glow.rs`）：32 位色深的 override-redirect 窗口，输入区域设为空（鼠标穿透），在单独的线程里逐帧 `PutImage`，像素由 `glow::render` 算。依赖窗口合成器，没有时不显示。暂不跟随系统的「减少动态效果」。
- **测试**：纯计算的部分是普通单元测试；需要 X 服务的测试标了 `#[ignore]`，CI 的 Ubuntu 任务用 Xvfb 跑（`xvfb-run -a cargo test -p flow-platform -- --ignored --test-threads=1`，xclip 充当"别的程序"）。Xvfb 里没有真实键鼠，测试用 XTest 模拟并让捕获接受 XTEST 设备。
- **外壳**（三套实现相同）：托盘依赖 libayatana-appindicator，GNOME 默认不显示托盘图标（要装扩展）；托盘菜单常常不显示勾选状态，所以「暂停共享」「锁定在本机」两项在 Linux 上用文字表示当前状态（暂停后变成「恢复共享」），「把键鼠切到」里各设备的状态也一律写成文字；安装包从 v0.2.2 起随正式版发布，应用内自动更新从 0.2.4 起接入（见第 10 节）。

### Wayland：显示器（`linux_wl.rs`）

用 `wl_output` 加 `xdg-output`：位置和尺寸取合成器的逻辑坐标，它本身就是与缩放无关的逻辑点；缩放 = 当前分辨率 ÷ 逻辑尺寸，分数缩放也能算对；没有 xdg-output 时退回整数缩放。显示器标识用输出名（`DP-1`、`eDP-1`）。Wayland 没有主屏的概念，取左上角在原点的那块。每块输出还记着它的全局对象编号（对所有连接都一样），其他模块据此在自己的连接里找到同一块输出。

### Wayland：wlroots 系（Sway、Hyprland）

- **注入**（`linux_wlr_input.rs`）：`zwlr_virtual_pointer`，每块显示器建一个绑定到该输出的虚拟指针（协议第 2 版），坐标就是这块屏幕内的逻辑点（按 1/16 点上报）；不能绑定输出时按全部显示器的外接矩形算。`zwp_virtual_keyboard` 要客户端自己上传键盘映射、自己上报修饰键状态：映射取本机键盘当前用的那份（没接键盘时用系统默认布局），修饰键状态用 xkbcommon 跟着按键算。注入的是物理键位，字符仍由本机布局和输入法决定。长按连发由收到按键的程序自己产生，对方发来的连发事件不注入。
- **捕获**：在通往别的电脑的屏幕边上各放一条 1 个逻辑点宽的透明 layer-shell 窗口（最上层），光标碰到它就合成一次向外推的移动（位置在边上、位移向外 3 个点）交给控制器。控制器决定切换后：把这条窗口铺满整块屏幕并独占键盘焦点，再锁定指针（`pointer-constraints`）、用 `relative-pointer` 读位移、请合成器不再处理快捷键（`keyboard-shortcuts-inhibit`）。铺满是为了不依赖合成器肯不肯锁：老版本的 sway 只给普通窗口锁定指针（实测 1.7），铺满之后光标怎么动都在窗口里，位移和按钮照样收得到，本机的其他窗口也收不到点击。回到本机时窗口缩回去、放开键盘，再用一个临时的虚拟指针把光标放到跨回来的位置（离屏幕边留 4 个点，之后 250 毫秒内碰边不算）。
  - **不碰屏幕边也能接管**（`Capture::apply_summon`，托盘菜单、`flowacross --switch` 用）：这时光标不在任何边缘窗口上，流界拿不到指针。做法是每块屏幕挑一条边缘窗口临时铺满整屏；窗口真的变大之后（合成器的 `Configure`）用虚拟指针发一次位移为零的移动，让合成器重新算光标在哪个窗口上并报"进入"，随即完成和上面一样的锁定，其余屏幕上铺开的窗口缩回去。没有边缘窗口的屏幕（它的哪条边都不通往别的电脑）接不住，光标在那里时要等它碰到一条边。在无头 sway 1.7 和 1.10 上测过；没有在 Hyprland 和真实鼠标上验证。
  - 边缘窗口会挡住屏幕最外一圈像素的点击，所以只放在通往别的电脑的边上。
  - Wayland 的事件不带来源：流界刚注入过鼠标移动的 150 毫秒内，光标碰到边不算（它是被远端推过去的）。
  - 按键事件没有连发，由流界按合成器给的重复速度自己产生（修饰键和 Caps Lock 不连发）。
  - 键盘一还给本机就收不到按键的抬起了，所以放开时替还按着的键补发抬起（portal 那套同样处理）。不补的话控制器会一直以为它们按着：触发切换的方向键会被一直"吞掉"，下次按快捷键要按两下才生效。
  - 合成器不锁定指针且有多块显示器时，看不见的光标可能移到另一块屏幕上，那时收不到鼠标事件，移回来才恢复。
- **剪贴板**（`linux_wl_clipboard.rs`）：`zwlr_data_control`，后台也能读写。结构和 X11 的一样：进程内唯一的后台服务负责应答。读：让数据源把某个格式写进套接字的一端，从另一端读到结束（文本和文件清单最多等 0.5 秒，图片 5 秒）；写：建数据源、声明格式、设为选区，收到请求时在单独的线程里写。自己写入时变化计数直接加一，合成器随后回报的那一次不再重复计数。格式名和 X11 相同。
- **边缘浮光**（`linux_wl_glow.rs`）：layer-shell 窗口，输入区域为空，按逻辑点的分辨率逐帧把 `glow::render` 的像素写进共享内存缓冲区。
- **测试**：`scripts/test-wayland.sh` 起一个无头的 sway（`WLR_BACKENDS=headless`、pixman 渲染），在里面串行跑标了 `#[ignore]` 的集成测试：注入的移动撞到屏幕边 → 上报向外推 → 锁定 → 位移、按键、按钮、滚轮、长按连发 → 放开后光标回位；只在指定的边上有反应；剪贴板和 wl-clipboard 双向互通（含 4 MB 图片）；浮光用 grim 截屏比对像素。CI 的 Ubuntu 任务每次都跑。无头合成器里没有真实键鼠，用虚拟指针和虚拟键盘模拟，并让捕获接受"自己注入的移动"。

### Wayland：GNOME / KDE（`linux_portal.rs`）

这两个桌面不提供 wlroots 的虚拟输入协议，对外的正式接口是 xdg-desktop-portal（D-Bus）加 libei。portal 和 libei 都是异步接口，全部放在一条常驻线程上跑（单线程的 tokio 运行时），对外仍是同步的句柄。必须是同一条：ashpd 全进程共用一条 D-Bus 连接，连接的读循环挂在创建它的那个运行时上；早先注入和捕获各建各的运行时，先建连接的那个一结束，连接就废了，另一边再也收不到回复（设备全部断开再连上之后就切不出去了）。

- **注入**：`RemoteDesktop` 会话。第一次要用户在系统弹窗里同意；拿到的恢复令牌存在 `$XDG_STATE_HOME/flowacross/remote-desktop.token`（权限 0600），之后不再弹窗。通过 `ConnectToEIS` 拿到连接后作为发送方，用合成器给的绝对指针、按钮、滚轮、键盘设备发事件；坐标是合成器的全局逻辑坐标，和显示器枚举是同一个坐标系。
- **捕获**：`InputCapture` 会话。在通往别的电脑的屏幕边上设屏障，光标撞上时合成器开始把键鼠交给流界（`Activated`），这时合成一次向外推的移动交给控制器；控制器不切换就立刻 `Release`。之后的位移、按钮、滚轮、按键从 EIS 连接（接收方）读，回到本机时 `Release` 并告诉合成器光标该放在哪。这个 portal 没有记住授权的机制，每次启动流界都会弹窗。
  - 撞上屏障的那一刻合成器就已经开始捕获，等不了「停留一会儿才切换」，这项设置在这里不起作用。
  - 合成器可以单方面结束捕获（GNOME / KDE 都留了强制退出的快捷键），流界不会立刻知道，要等心跳超时或再次撞到屏幕边。
- **授权弹窗**（`prompt`）：
  - **限时 60 秒、自动关闭**（`AUTH_TIMEOUT`）：到时间没人点，流界把弹窗关掉，算作没有授权；不会一直挂在屏幕上。等待期间主界面有一条横幅显示倒计时（`flow_platform::pending_authorization` → `StateView::auth_prompt`，引擎每 2 秒看一次有没有弹窗在等，秒数由界面自己往下数）。
  - **同一时刻只弹一个**：注入和捕获各要一次授权，排着来。
  - **怎么关掉弹窗**：ashpd 发请求用的标识是它内部随机生成的，拿不到，所以向 portal 自省本连接的请求路径（`/org/freedesktop/portal/desktop/request/<连接名>`），把等待期间新出现的请求逐个 `Close`；注入那一个另外把会话也关掉。
  - **停止不再卡住**：停止捕获只发一条命令就返回，不等任务结束；启动阶段的每一步（包括等弹窗）都和"停止"赛跑（`unless_stopped`），被叫停时弹窗跟着关掉。以前停止要等线程退出，弹窗没人点就一直卡着引擎的维护循环。
  - **每次需要都会再问**：被拒绝、超时、或者桌面后来把权限收回（`PlatformError::Denied`）之后不是到进程退出都不再申请。捕获：有设备连上时重新申请（`Engine::ensure_capture`）；注入：下次有电脑把键鼠切过来时重新申请（`Engine::on_enter` → `inject`）。不按时间自动重试——那等于隔一阵就弹一次窗；同一次被控制期间也只问一次，不会每个键鼠事件都弹。主界面在没拿到授权时有一条横幅和「重新授权」按钮（`StateView::auth_denied`、`retry_authorization`），不用等到"下次需要"。读写剪贴板不会触发弹窗，沿用现有的会话。
  - 启动后才出的问题（3 秒后才被拒绝、运行中桌面收回权限）引擎也能知道：`InputCapture::failure` 报告捕获自己停了的原因，维护循环查到后把它卸掉、把键鼠还给本机、提示原因。以前这种情况捕获静默失效，没有提示也不会重启。
- **剪贴板**：KDE 有 data-control，直接用上一节的实现；GNOME 没有，用挂在 `RemoteDesktop` 会话上的 `Clipboard` portal（读写都是 portal 给的文件描述符），所以 GNOME 上剪贴板要等用户同意远程桌面的弹窗之后才能用。
- **边缘浮光**：KDE 有 layer-shell，用上一节的实现；GNOME 没有，不显示。
- **启动**：弹窗可能很久没人点，启动只等 3 秒：很快失败的（没有 portal、桌面版本太旧）当场报错，其余在后台继续，期间注入的输入直接丢弃。捕获启动时顺便把注入用的会话也启动起来，让授权弹窗在用户还坐在这台电脑前时出现。
- **版本要求**：`InputCapture` 和 `ConnectToEIS` 需要 GNOME 45 / KDE Plasma 6.1 以上。
- **验证情况**：这一部分只做到编译通过和纯计算部分的单元测试（屏障坐标、滚动量换算、令牌路径、请求路径和自省结果的解析、倒计时、启动阶段让位给停止）。portal 的授权弹窗要人来点，无头环境里跑不起来，**整条链路没有运行过**，需要在 GNOME 和 KDE 的真机上验证；其中"向 portal 自省出待处理的请求再关掉"这一步依赖 xdg-desktop-portal 的 D-Bus 实现会列出下级对象，没有对照过真实的 portal，关不掉时弹窗会留到用户自己关。
