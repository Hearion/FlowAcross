# 流界 FlowAcross 技术架构

> 一套键鼠，自由跨屏。本文档记录第一版（v1）的技术选型和关键设计，随开发持续更新。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 核心逻辑 | Rust（`crates/flow-core`） | 无 IO 的纯逻辑：布局、坐标换算、切换判定、按键状态、协议编解码。可在任何平台单测。 |
| 平台层 | Rust + 各平台系统 API（`crates/flow-platform`） | macOS：CGEventTap / CGEventPost / NSPasteboard；Windows：低级键鼠钩子 + Raw Input / SendInput / 剪贴板监听。 |
| 网络层 | Rust：QUIC（quinn + rustls）+ mDNS（mdns-sd）（`crates/flow-net`） | QUIC 自带 TLS 1.3 加密；可靠流传按键，不可靠数据报传鼠标绝对坐标；剪贴板走独立流，大文本不会阻塞输入。 |
| 桌面外壳 | Tauri 2（`app/src-tauri`） | 体积小、常驻内存低，托盘/菜单栏、开机启动、单实例都有官方插件。 |
| 界面 | React + TypeScript + Vite（`app/src`） | 设备布局图需要拖拽交互，Web 技术实现最省力。视觉规范见 `docs/design.md`。 |

## 2. 进程与模块关系

```
┌──────────────────────── 流界（单进程）────────────────────────┐
│  UI (WebView, React)  ←── Tauri commands / events ──→  Engine │
│                                                        │      │
│        ┌───────────────┬───────────────┬───────────────┘      │
│        ▼               ▼               ▼                      │
│  flow-platform     flow-net        flow-core（纯逻辑）         │
│  键鼠捕获/注入      发现/配对/QUIC   布局·切换·按键·协议        │
│  剪贴板/权限/休眠                                               │
└───────────────────────────────────────────────────────────────┘
```

- **Engine**（位于 `app/src-tauri`，后续可下沉为独立 crate）是一个 actor：接收平台事件、网络事件和 UI 命令，调用 `flow-core` 做决策，再驱动平台层和网络层执行。
- 每台电脑运行同一个程序，**对等**架构，没有固定的"服务端"。正在被用户物理操作的那台叫 **源设备**，被远程控制的叫 **目标设备**。任何一台都可以成为源。

## 3. 统一坐标空间

所有设备的所有显示器放在一个 **布局空间** 里，单位是 **逻辑点**（与缩放无关，≈ macOS 的 point、Windows 100% 缩放下的像素）。

- 每块显示器：`rect`（布局空间中的位置和逻辑尺寸）+ `scale`（缩放系数，物理像素 = 逻辑点 × scale）。
- 用户在布局图里拖动卡片，修改的就是 `rect.origin`。拖动时自动吸附到相邻卡片边缘。
- **鼠标速度**：平台层上报的位移已换算成逻辑点（macOS 事件本身就是逻辑点；Windows 钩子给的是物理像素，除以所在显示器的缩放），在目标显示器上按逻辑点移动。这样 4K@200% 和 1080p@100% 之间移动的"手感距离"一致。
- **跨边映射**：默认"连续映射"——光标从边缘离开时，沿边方向的布局坐标保持不变（和同一台电脑多显示器一致）；可选"按比例映射"——按边长比例换算，适合尺寸差很大的屏幕。

## 4. 切换与防误触

`flow-core::switching` 是纯函数状态机，输入"光标贴边事件 + 当前时间 + 按住的修饰键"，输出"切换 / 不切换"。

- 边缘必须有相邻显示器（布局里真正贴着）才会切换。
- 可选：按住指定修饰键才允许跨屏。
- 可选：贴边停留 N 毫秒才切换（停留期间离开边缘则重新计时）。
- 可选：角落死区，避免触发 macOS 触发角 / Windows 开始菜单时误切。
- 锁定：临时把键鼠锁在当前设备，边缘切换失效（快捷键仍可解锁）；其他设备也不能新切进来（正在控制本机的那台不受影响，见下文"暂停与锁定"）。
- **暂停与锁定也挡住别人控制本机**（`flow-core::switching::accepts_control`，0.1.7 起）：暂停共享、暂停某台设备时两个方向都停，正在控制本机的那台立即结束并释放按键；锁定只挡新进来的——用户可能正是用对方的键鼠点了本机的「锁定」，意思是"留在这台"。本机在会话建立时和状态变化时发 `Availability { accepting }`，对方据此不再切过来、正在控制的回到它那边，界面显示「对方已暂停」。目标侧收到 `Enter` 时也会再判断一次（对方没来得及收到通知，或是旧版本），不接受就忽略它之后的输入。
- 按住鼠标按钮时不切换（v1 不支持跨设备拖拽，避免拖到一半按钮状态错乱）。
- 停留计时只在"往外推"时开始，单纯停在边上（比如点贴边的滚动条）不会触发。
- 快捷键 Ctrl + Alt + ←/→（Mac 上 ⌃⌥←/→）切到布局中左右相邻的设备，不受边缘规则和锁定限制。
- 光标到达通往其他设备的边的最后一个逻辑点、且仍在朝边移动，就算"推出边缘"（系统会把光标限制在屏幕内，贴边后继续推不一定有位移）。

### 跨屏控制流程

- **源设备**：有已连接的设备时启动全局键鼠捕获（macOS CGEventTap，Windows 低级钩子）。捕获回调同步调用 `input::Controller`，它只做内存计算并把消息投进会话的发送通道，决定每个事件放行还是拦截。
  - 本机状态：把光标位置换算到布局空间，交给 `EdgeSwitcher` 判断是否切换。
  - 控制远端：拦截全部输入；`VirtualCursor` 在布局空间里按相对位移移动，把目标显示器内的绝对坐标发过去（`Enter` / `MouseMove`），按键和按钮按 `InputRouter` 分到"按下时所在的一边"。
  - 光标锁定：macOS 断开鼠标与光标的关联并隐藏光标；Windows 把光标停在离开的那个边缘点并拦截移动（暂不隐藏）；低级钩子上报的坐标不会被限制在屏幕内（实测），所以停在边上也能测到往外的位移。回到本机时光标放到跨回来的位置。
  - 控制期间每 500 毫秒发一次 `Heartbeat`；对方支持时 1.5 秒收不到 `HeartbeatAck` 就回到本机（见第 6 节）。
- **目标设备**：只接受当前控制者的输入并注入（macOS CGEventPost，Windows SendInput），同时记录它按下的键。收到 `Leave`、会话断开、或 3 秒没有任何消息时释放全部按键。
- **接管**：同一时刻只能有一个控制方，谁的物理键鼠在动谁就是源。A 控制 B 时，用户直接拿起 B 的鼠标推到 A：B 的控制器照常进入 A 并发 `Enter`，同时 B 结束"被 A 控制"（释放 A 按下的键，不再注入 A 的输入）；A 收到 `Enter` 时如果自己正在控制别的设备，先 `Controller::yield_control()`——释放远端按键、发 `Leave`、解锁本机光标但不挪动它——再接受 B 的控制。否则两边都以为自己是控制方，A 的光标一直被锁、本机键鼠被拦截转发，表现为流转异常、切不回来。
- 流界自己注入的事件带标记（macOS 事件 user data，Windows dwExtraInfo），捕获时直接放行，不会被当成本机输入。
- 鼠标坐标走 QUIC 数据报（`flow-net::moves`）：每条带递增序号；接收方一次读完已到达的数据报，只注入最新的一个，过时和乱序的丢掉。网络短暂停顿后光标直接跳到当前位置，不会像可靠流那样把积压的位置逐个重放。只有对方版本 ≥ 0.1.3（`DATAGRAM_MOVES_SINCE`）时才发数据报，否则仍走可靠流；点击、按键、进入/离开等其他消息始终走可靠流。数据报发送缓冲只有 16 KB，拥塞时 quinn 丢弃最旧的。
- 发送端对鼠标位置节流（`flow-core::throttle`）：两次发送至少间隔 4 毫秒，间隔内只保留最新位置，其他消息到来时先把待发位置发出。高回报率鼠标每秒上千个事件，逐条发送会让网络排队、远端注入跟不上而卡顿。「结束控制远端」日志记录这次的按键数、鼠标事件数和时长，可据此估算回报率。
- 已知网络问题：Mac 用 Wi‑Fi 时，AWDL 大约每 0.5 秒造成一次 60–100ms 的网络停顿（实测，关掉 awdl0 后消失），表现为跨屏每秒卡一下。鼠标位置改走数据报后，停顿后直接跳到最新位置，但停顿本身仍在；实测仍能感到卡顿，所以提供低延迟模式。
- **低延迟模式**（仅 macOS，`flow-platform::low_latency`，默认关闭）：第一次开启时通过 `osascript … with administrator privileges` 安装一个 launchd 守护进程（`/Library/LaunchDaemons/app.flowacross.awdl-guard.plist`，脚本在 `/Library/Application Support/FlowAcross/`，root 所有）。脚本和 plist 的内容以 base64 直接写在 root 命令里（`flow-platform::root_install`），由 root 写进只有 root 能写的目录、改名就位；不经过用户可写的临时文件，否则授权弹窗停留期间同一用户下的其他进程可以把文件换掉，换来以 root 身份常驻执行（0.1.6 及以前的问题）。守护进程每 0.5 秒检查：标志文件 `/tmp/app.flowacross.lowlatency` 存在且流界在运行时保持 `awdl0` 关闭，否则恢复它关掉的 AWDL。引擎在"开启了且有设备连着"时创建标志文件，断开、关闭开关、退出时删除；标志在 /tmp，重启自动清除；流界异常退出时守护进程也会恢复。设置里可以移除后台服务。
- 流界大部分时间在后台运行，启动时调用 `flow_platform::keep_responsive()` 关闭系统对后台程序的降速：macOS 登记延迟敏感活动并在 Info.plist 声明 `LSAppNapIsDisabled`（关闭 App Nap），Windows 关闭本进程的电源节流（EcoQoS）。否则打包后的正式版跨屏会卡顿。
- Windows 上进程注册了键盘 Raw Input 时，只要它自己的窗口在前台，系统就不再调用它的低级键盘钩子（实测）。Tauri 的窗口库 tao 默认会注册，所以外壳用 `DeviceEventFilter::Always` 关掉设备事件，否则流界窗口在前台时键盘到不了远端。

## 5. 键盘

- 网络上传输 **USB HID 键码**（Usage Page 0x07），与系统和键盘布局无关。平台层负责 macOS 虚拟键码 / Windows 扫描码 ↔ HID 的双向转换。
- 传 **物理按键** 而不是字符，目标电脑的输入法照常处理按键，因此中文、日文等输入法体验保持不变。
- 组合键：修饰键作为普通按键按下/抬起，天然支持任意组合。修饰键由 **目标侧** 换算（`engine::map_key`）：
  - Mac 控制 Windows：⌘ ↔ Ctrl 互换，在 Mac 上按 ⌘C，Windows 收到 Ctrl+C。
  - PC 键盘控制 Mac：按 Mac 上的设置「Windows 键盘的修饰键」（`Settings::win_keys`，`flow-core::keys::WinToMacKeys`）——Windows 习惯（默认，Ctrl → ⌘、Win → ⌃，与旧版本一致）/ Mac 键位（空格旁的 Alt → ⌘、Win → ⌥）/ 直通（Win → ⌘）/ 自定义（Ctrl、Win、Alt 各自指定 ⌃⌥⌘ 之一，左右键分别对应）。因为是目标侧换算，这项设置只在 Mac 的设置页出现；不改协议，对方版本无要求。引擎把当前对应关系存一份在单独的锁里，注入按键时不拿 `state` 锁，改设置立即生效。
- 长按：注入的按键不会被目标系统自动连发，因此转发源设备系统产生的连发事件（`repeat = true`）。
- **按键状态跟踪**（`flow-core::keys::PressedState`）：源和目标两侧都记录"已按下但未抬起"的键和鼠标按钮。切换离开、断网、心跳超时、休眠时，目标侧自动释放全部按键，源侧恢复本机输入——避免"卡键"。
- 已知系统限制：Windows 的 Ctrl+Alt+Del、UAC 安全桌面无法注入；向管理员权限窗口注入需要流界本身以管理员运行。在界面中给出说明。

## 6. 网络、发现与配对

- **发现**：mDNS 服务 `_flowacross._udp.local.`，TXT 记录含设备 ID、名称、系统、协议版本、证书指纹前缀。
- **身份**：每台设备首次启动生成一对长期密钥和自签名证书（保存在应用数据目录，私钥文件权限 0600），设备 ID = 证书 DER 的 SHA-256 指纹。
- **TLS**：QUIC 双向证书认证。TLS 层只校验握手签名（证明对方持有私钥），证书是否可信由应用层按指纹判断。通过 mDNS 发现的地址连接后，必须核对证书指纹就是要连的设备。
- **发现的数据不可信**：mDNS 可以被局域网里任何人伪造。TXT 里的设备 ID 必须是 64 位小写十六进制（`DeviceId::is_well_formed`），否则丢弃；名称一律经 `protocol::clean_name` 去掉控制字符、截到 64 个字符（`Hello`、`Profile` 里的名称同样处理）。日志里截断 ID 用 `DeviceId::short`（按字符截断，不会 panic）。
- **配对**（`flow-core::pairing`，0.1.7 起）：带承诺的 6 位配对码。发起方先发随机数 `nI` 的承诺 `PairCommit(H(fpI, nI))`，响应方回 `PairNonce(nR)`，发起方再公开 `PairNonce(nI)`，响应方核对承诺；配对码 = H(fpI, fpR, nI, nR, TLS 通道绑定值)。双方界面都显示配对码，用户核对一致并在两边都点"确认"后，互相保存对方指纹为可信设备。只用两个指纹算码时，中间人可以反复换证书离线凑出两边相同的码（0.1.6 及以前的问题）；有了承诺，每边的码都取决于中间人出牌时还不知道的随机数，每次尝试只有百万分之一的机会，通道绑定值让码只对这一条 TLS 连接成立。对方版本低于 0.1.7（`SECURE_SINCE`）时不配对，提示两边都更新；已经配对过的旧版本设备照常连接。别人发起的配对请求每分钟最多弹 3 次。
- **未认证连接的限制**：同时处在握手 / 配对阶段的入站连接最多 8 个，超出的直接拒绝；进入会话（双方互信）之前单帧最大 16 KB（`HANDSHAKE_FRAME_LEN`），之后放开到 8 MB。日志只保留最近 14 天。
- **握手**：发起方先发 `Hello`（含 `trusts_you`：是否已信任对方）。双方互相信任 → 直接建立会话并交换显示器信息；否则只有用户主动发起时才进入配对（`PairRequest` → 双方各自 `PairConfirm`），自动重连遇到对方不再信任时提示"需要重新配对"。
- **重连**：每 2 秒检查一次离线的已配对设备，地址优先用 mDNS 最新结果，其次用上次成功连接的地址；指数退避 2s→30s，mDNS 重新发现设备时立即重试（不重置次数）。设备离线后最多自动重试 5 次（约 30 秒），仍失败就停止，标记为「已断开」等用户手动连接；对方的流界启动时会主动连过来，手动连接失败也不恢复自动重试。设备 ID 较小的一方先连，较大的一方晚 6 秒；万一两边同时连上，双方都保留"发起方 ID 较小"的那条连接，结果一致。
- **移除**：一方移除设备时发送 `Bye(Removed)`，对方收到后也删除可信记录。
- **通道**：
  - 控制流（可靠有序）：握手、进入/离开、按键、鼠标按钮、滚轮、心跳、剪贴板文本、文件清单。
  - 数据报（不可靠）：鼠标绝对坐标，丢一个无所谓，下一个会覆盖。
  - 传文件的流（可靠，按需新开）：复制的文件内容，每次传输在同一条连接上另开一条双向流（`flow-net::link::open_stream`），大文件不会阻塞控制流里的键鼠消息。
- **心跳**：进入远程控制后每 500ms 一次；目标侧 3s 未收到任何消息即释放全部按键并结束远程会话。0.1.7 起目标侧对每个心跳回 `HeartbeatAck`，控制方 1.5 秒收不到回执就认为断网：释放远端按键、恢复本机输入并提示，不用等 QUIC 的 8 秒空闲超时。对方版本低于 0.1.7 时不回执，仍按 QUIC 超时处理。

## 7. 剪贴板（文本与文件）

系统剪贴板没有跨平台的变化通知，引擎每 0.5 秒读一次变化计数（macOS `changeCount`，Windows `GetClipboardSequenceNumber`），有新文本就通过 `ClipboardSync` 发给已连接且未暂停的设备；写入远端内容后记下新的计数，避免回传。

- 纯文本超过 4 MB 的不同步；图片等其他格式暂不同步。
- 每条内容带 `(来源设备, 序号)`，写入远端剪贴板后不会再被回传，避免回环。对方重启后序号从 1 重新开始，所以每次和它建立会话时忘掉之前记下的最大序号（`ClipboardSync::forget`），否则对方更新、重启后的前若干次复制会被当成旧消息丢掉。
- 可以全局关闭，也可以按设备关闭。

### 跨设备复制文件

用法和文字一样：在 Finder / 资源管理器里复制文件，把键鼠切到另一台，粘贴。

1. **只发清单**：剪贴板变化时先看是不是文件（macOS 读 `public.file-url`，Windows 读 `CF_HDROP`）。是文件就在后台线程遍历一遍，算出文件数和总大小，发 `FileOffer`（编号、顶层名称、文件数、字节数）给支持的设备，不发内容。剪贴板换成别的内容时发一个空清单撤回。新连上的设备会补发当前清单。
2. **什么时候取**（`flow-core::files::OfferBook`）：接收方只记最新的一份清单。键鼠来到本机时（开始被控制，或控制远端后回到本机）自动去取；清单在键鼠来到后 2 秒内才到、或本机正被控制时收到，也自动去取。超过 1 GB 的不自动取，侧栏显示「接收」按钮。本机又复制了别的、或收到其他设备的文字时，旧清单作废。
3. **传输**：接收方在同一条 QUIC 连接上新开一条流，发 `FileRequest { id }`；发送方重新遍历文件，依次发 `FileEntry`（`/` 分隔的相对路径、大小、是否目录）和 `FileChunk`（每块最多 256 KB，按字节串编码），最后 `FileEnd`；出错发 `FileError`（原因直接显示给用户）。编号对不上（发送方剪贴板已经换了）也回 `FileError`。
4. **落盘**：先写进接收文件夹（下载文件夹里的「流界」）中的临时目录 `.flowacross-*`，全部收完再移出来，重名时改成「报告 (1).pdf」。中途失败或取消就删掉整个临时目录；启动时清理异常退出留下的。`flow-core::files::Incoming` 校验消息顺序和大小，路径里的绝对路径、`..`、Windows 不允许的字符和保留名（CON、NUL…）一律拒绝或替换。目录里的符号链接和 `.DS_Store`、`Thumbs.db` 这类系统文件不传。
5. **写入剪贴板**：收完后把文件路径写入本机剪贴板（Windows 另写 `Preferred DropEffect = 复制`，粘贴时不会当成剪切），然后提示「可以直接粘贴」。如果接收期间用户又复制了别的（剪贴板的"代"变了），就不覆盖剪贴板，只提示文件保存在哪里。
6. **取消与进度**：一次只接收一份，新的取代还没收完的旧的。侧栏「文件」面板显示进度（最多每 200ms 推一次），两边都能取消；接收方取消后发送方的写入立即失败并停止。
7. **兼容**：`FileOffer` 等是协议里的新消息，旧版本解析不了会断开连接，所以只发给版本 ≥ 0.1.5（`FILE_TRANSFER_SINCE`）的设备；不按"版本号相同"放行，因为开发版本和已发布的同号版本协议不同。对旧版本照旧只发文字（Finder 复制文件时附带的文件名）。两台电脑联调开发版本前，先把版本号改到 ≥ 0.1.5。
8. **开关**：设置里「复制文件」跟随「共享剪贴板」，可以单独关掉；暂停共享、暂停某台设备时也不收发。

## 8. 系统权限

| 平台 | 权限 | 用途 |
|---|---|---|
| macOS | 辅助功能（Accessibility） | 注入键鼠事件、拦截本机事件 |
| macOS | 输入监控（Input Monitoring） | 捕获键盘事件 |
| macOS | 本地网络 | mDNS 发现与局域网连接 |
| Windows | 防火墙放行 | 首次监听端口时系统弹窗 |

首次引导页逐项检测并给出"打开系统设置"按钮。

## 9. 失败处理原则

任何异常（断网、对端休眠、注入失败、心跳超时、权限被撤销）都遵循同一顺序：

1. 目标侧释放全部按键和鼠标按钮；
2. 源侧立即停止拦截，本机恢复可用，光标回到离开时的边缘（断网时靠心跳回执在 1.5 秒内发现，见第 6 节）；
3. 界面和托盘显示明确原因 + 处理建议（如"对方电脑已休眠，唤醒后会自动重连"）。

**配置文件损坏**（`config::Config::load`）：`config.json` 解析不了时，先改名备份为 `config.json.bad-<时间戳>`，再用默认配置继续运行，主界面一直显示原因和备份位置，直到用户点「知道了」。连改名都失败（比如没有权限）时，这次运行不写配置，避免覆盖原文件。以前是静默用默认配置，下一次保存就把所有配对覆盖掉了。

## 10. 打包与自动更新

- **打包**：推送 `v*` 标签后由 GitHub Actions（`release.yml`）用 tauri-action 打包 Windows NSIS 安装包和 macOS 通用版（.dmg + `.app.tar.gz`），发布到公开仓库 `Hearion/FlowAcross-releases`。源码仓库私有，App 无法匿名下载其中的文件，所以安装包单独发布。
- **更新清单**：每次发布带一个 `latest.json`（版本号、更新说明、各平台下载地址和签名）。App 读取 `releases/latest/download/latest.json`。
- **签名**：更新包用 minisign 私钥签名（私钥只在 GitHub Secrets 和开发者本机），公钥写在 `tauri.conf.json`，App 下载后先验签再安装。本地打包不生成更新包，不需要私钥（CI 打包前才打开 `createUpdaterArtifacts`）。
- **App 端**（`app/src-tauri/src/updater.rs`，`tauri-plugin-updater`）：发布版启动 15 秒后、之后每 6 小时检查一次（设置里可关），只提示不自动安装。用户确认后：下载（引擎照常工作，失败不影响使用）→ `Engine::shutdown()` 释放远端按键、恢复本机输入、断开连接 → 安装 → 重新打开。安装失败时提示原因并提供「重新打开流界」。
- **macOS 授权**：系统按代码签名记住辅助功能/输入监控授权。CI 用固定证书（`APPLE_CERTIFICATE`）签名，更新后授权保持有效；没有证书时退回 ad-hoc，每次更新都要重新授权。
- 发版步骤和一次性配置见 `docs/release.md`。
