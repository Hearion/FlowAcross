# 流界 FlowAcross 开发路线图

每个里程碑结束时都应当"能跑、能测、能演示"。勾选表示已完成。

## M0 工程基础

- [x] 技术选型与架构文档
- [x] Rust workspace + Tauri 2 + React 骨架
- [x] `flow-core`：布局空间、跨边映射、切换判定、按键状态跟踪、协议编解码、配对码
- [x] `flow-core` 单元测试
- [x] `flow-platform` trait 定义
- [x] CI：macOS、Windows、Ubuntu 上跑 fmt / clippy / test（`.github/workflows/ci.yml`，已在 GitHub 上通过；Ubuntu 上另跑 X11、Wayland 的平台层测试和发版脚本的测试）
- [x] 界面视觉设计（布局图、跨屏边、设置面板）

## M1 本机输入（平台层）

- [x] macOS：CGEventTap 捕获并可拦截键鼠；CGEventPost 注入；虚拟键码 ↔ HID
- [x] Windows：低级钩子捕获；SendInput 注入；扫描码 ↔ HID；Per-Monitor DPI v2（仅通过交叉编译检查，待真机验证；Raw Input 视需要再加）
- [x] 枚举显示器（位置、逻辑尺寸、缩放）：macOS 已实现；Windows 已实现、仅通过交叉编译检查，待真机验证
- [x] 权限检测与跳转系统设置（macOS：辅助功能、输入监控）
- `flow-cli` 调试工具（录制本机输入 / 回放注入）：没有做，搁置。当初是为了在接上网络之前单机验证平台层，后来平台层直接用端到端的真机互控（M3）和 Xvfb / 无头 sway 里的集成测试验证了，不再需要它来验收。

**验收**：原定用 `flow-cli` 回放验证，实际由 M3 的真机互控验收代替。

## M2 网络、发现与配对

- [x] 设备身份：密钥 + 自签名证书，本地持久化
- [x] mDNS 广播与发现
- [x] QUIC 连接：双向证书认证 + 控制流（数据报、剪贴板流随 M3/M5 加入）
- [x] 配对流程：双方显示 6 位码、双方确认、保存可信设备；移除时双方同步删除
- [x] 自动重连（退避、mDNS 重新发现立即重试、上次地址兜底；约 30 秒内重试 5 次仍失败就停止，改为手动连接）
- [x] 两台真机互相发现与配对的手动验证（Mac + Windows）

**验收**：两台电脑互相发现，完成配对，重启应用后自动重连。

## M3 跨屏控制（端到端）

- [x] Engine 状态机：本机 / 控制远端 / 被控制（`app/src-tauri/src/input.rs` + engine）
- [x] 边缘切换 + 快捷键切换（Ctrl+Alt+←/→）+ 锁定
- [x] 防误触：修饰键、停留时间、角落死区
- [x] 源侧拦截本机输入、隐藏并锁定本机光标（Windows 把光标停在离开的那个边缘点，暂不隐藏）
- [x] 心跳、超时释放、断网恢复本机
- [x] Mac ⌘ ↔ Win Ctrl 互换（Mac 与 Windows 之间自动启用）
- [x] Mac ↔ Windows 真机互控验证（点击、滚动、拖拽、打字、中文输入法、断网不卡键）：v0.2.2-beta.6 / beta.7 上开发者按清单验证通过

**验收**：Mac 和 Windows 互控，能正常点击、滚动、拖拽、打字（含中文输入法），拔网线后两边都不卡键。

## M4 界面与引导

- [x] 首次引导：设备名称 → 权限 → 发现附近设备 → 配对
- [x] 设备布局图：拖动卡片、吸附、多显示器、当前控制高亮、连接状态（布局保存在本地配置）
- [x] 托盘 / 菜单栏：暂停共享、锁定、「把键鼠切到」指定设备（设备详情里也有同样的按钮）。键鼠所在的电脑上直接切；在被控制的电脑上点，则发 `SwitchTo` 请控制方来切。控制器和两台引擎的回环测试通过，托盘子菜单的内容有单元测试；开发时菜单本身没有在三个系统的真实托盘里点过（Linux 的托盘对动态改菜单的支持尤其要看一下）；v0.2.4-beta.1 经开发者本人按测试清单测试通过，随 v0.2.4 正式发布（具体测了哪些系统和桌面没有记录）
- [x] 设置页：防误触、剪贴板、开机启动；快捷键自定义（设置 › 快捷键：左右切换可改可关，每台电脑一个"切过去"的快捷键）。录制、重复检查、不合法的组合键在浏览器预览里点过；**没有在打包后的应用里录制过**（各系统的 WebView 上有些组合键会被系统截走）
- [x] 连接失败的原因与建议文案：找不到设备、防火墙 / VPN 拦截、不在同一网络、版本不兼容等，显示在设备详情和「添加设备」窗口里（`flow-core::diagnose`，见架构文档第 6 节）。原因是按现象推断的，单元测试覆盖了各种判断；**没有在真的被防火墙拦住、跨网段的环境里对照过**

    - 屏幕上有菜单展开时（合成器把鼠标交给了那个菜单）穿不过去，关掉菜单即可，流界这边改不了
    - [x] 切到 Mac 后滚轮很慢：Mac 注入时一格只滚 1 行，改成 3 行（Windows、Linux 控制 Mac 都受益）
    - [x] 大写锁定两边相反：控制方把本机的状态告诉对方，对方对齐。Linux（X11、Hyprland / Sway）做控制方、macOS 和 Linux（X11、Hyprland / Sway）做被控制方时生效，sway 和 Xvfb 里有测试
    - [x] 大写锁定同步补到 macOS 和 Windows：做控制方时每次切过去查一次本机状态告诉对方，Windows 做被控制方时对齐（Windows 部分仅通过交叉编译检查，待真机验证）
